What I'm building

in progress · Nov 2026

payments-platform

A real-time payments platform built the way a bank would build it, from the domain model up: a double-entry ledger with idempotent transfers, change data capture into Kafka, stream processing for limits and fraud signals, and a lakehouse with dbt marts that reconcile back to the ledger.

ledger-service (Java 25, Spring Boot 4) ─ Postgres + outbox
   └─ Debezium CDC ─▶ Kafka 4 (Avro) ─▶ Kafka Streams (spend windows, alerts)
                              └─▶ Iceberg + dbt ─▶ marts, reconciliation, Dagster checks

in progress · Nov 2026

dataops-agent

A terminal agent with a data engineer's job. When a freshness or volume check fails on the payments platform, it investigates (lineage, logs, runbooks via retrieval), reconciles the affected marts against the ledger, and drafts a dbt fix as a pull request, behind a human approval gate. Built with evals first, MCP tools, tracing and cost per run.
